# keyword-search-aggregator

**指定一个关键词，把公开网络上跟它相关的东西收成一份报告 —— 并且明确告诉你「我没抓到什么」。**

输入一个词，输出一个单文件 HTML。中间做四件事：多通道发现、抓正文、抽时间、归并转载，入库前过一遍 PII 脱敏。

默认不装浏览器、不引代理池、不存全文；另有一个**默认关闭**的 Scrapling 隐身抓取档，需要时显式开启（见下文）。

---

## 为什么需要它

搜索引擎会给你 10 条链接，但不会告诉你这 10 条是怎么来的、少了什么。真跑起来会撞上三个坑，这个项目就是围着它们设计的。

### 1. 一个关键词只有 10 条

Bing 在匿名访问下**翻页完全失效**：`first=1/11/21`、去掉 `count`、加 `FORM=PERE`、换 `www.bing.com` + `mkt=en-US`、保持同一 session Cookie、直接照抄页面自带的「下一页」链接（带 FPIG 令牌）—— 返回的都是同一批 10 条，重合度 10/10。中英文查询结论一致。

能扩量的只剩一个办法：**换说法再搜**。项目内置查询变体矩阵（基词 + 修饰词），按实测增益排序，连续两个变体零新增就停手 —— 剩下的请求纯属浪费配额和风控预算。

修饰词还要**按查询类型选**：技术词加「左旋 右旋」「java」实测有增益，但同一套后缀打在时政词上是纯浪费（实测「央行降准」两个变体全被降级）。所以变体不是一开始就生成好的 —— 先只用基词打第一枪，用结果的域名与标题构成探测词类型（技术词 / 时政新闻 / 人名 / 判不出），只有判成技术词才追加修饰词。人名永远只打基词：任何「人名 + 第二个词」的组合都会触发 Bing 静默降级，收窄只能靠结果内归因。

### 2. 搜索引擎会「静默降级」，而且看起来完全正常

查询里一旦出现「人名 + 第二个词」，Bing 会把整条查询退回成**第一个词**的字面结果：

| 你搜的 | 实际返回 |
|---|---|
| `张军 南京` | 10 条全是「张」的百科 / 姓氏 / 家谱页 |
| `网络安全张军` | 测速网、网速测试 |
| `某某大学计算机学院张军` | 所在城市的旅游攻略 |

而 HTTP 是 **200**、`<title>` 还是原查询、搜索框 value 还是原查询、没有任何风控提示。唯一的可辨特征：**10 条结果里没有一条真的提到查询里的人名**。

危险在于这种页面「看起来是成功的」：上游拿到 10 条候选、断言通过、报告写「覆盖 10 个来源」，实际全是噪声。所以判定必须发生在**通道层**（拿到候选的第一时间），不能等下游按分数筛。

判定逻辑在 `kwsearch/discover/quality.py`，三条判据按查询形态选一条，刻意保持形式可解释、不做语义猜测。关键是**宁可漏判，不能误杀**：整页丢弃的代价远大于放过一页噪声。

同一模块里还有一条**不依赖查询词的结构判据**（`check_boilerplate`）：搜狗微信对「微信生态里搜不到」的词会返回一个兜底页 —— 列表结构完整，但「结果」标题要么全是站点名（「搜狗搜索」），要么整页反复给同一条。它的提示语里原样写着查询词，语义体检会误判成「相关」，只能靠结构识别：标题是站点名 → 整页丢；标题去重后只剩一个且 ≥3 条 → 整页丢（2 条可能是同一篇被两家转载，不误杀）。

### 3. 转载会把一个来源放大成十个

同一篇稿子被 N 个站转载，报告看起来「内容丰富」，实际只有一个信源。项目用 SimHash 做近重复归并，**阈值取 10，不是教程里常见的 3** —— 实测「原文 + 追加 180 字免责声明」（门户转载最标准的做法）距离是 8，阈值 3 会全部漏掉；而无关文章的距离在 23~35。

去重分两层，别混：**同一篇文章换了 URL**（搜狗微信的中转链每次请求换 token，URL 每次都不同）靠通道给的业务键 `dedupe_key`（公众号+标题+日期的哈希）在入库前识别，命中就复用库里那一条、不新建 doc，报告漏斗里记为「同文换链」；**同一篇稿子被不同站点转载**（URL 本来就不同）才靠 SimHash 做正文级归并。前者治「重复入库」，后者治「来源虚胖」。

折叠后每组要挑一条当代表，而挑代表同样是个坑：转载版挂着免责声明，字数反而比原文多，按「谁最长」选就会让二手站冒充原文。所以代表按**剥掉首尾转载模板后的长度**排（`body_core`），长度相同才看发布时间。剥离失手时（剥完只剩模板）会退回原文，宁可代表选错，也不能把文章删成一句话。

没参与归并的条目在报告里分三种写法：**待补算指纹**（有正文没指纹，重跑该词会自动补）、**正文过短**（本来就没有区分度）、**无正文**（抓取失败或 robots 拒绝）。合成一个「未判」数字等于没说。

## 看一眼输出

`report/<关键词>/index.html`，单文件、内联 CSS、零外部资源，双击就能开。固定七个区块：

| # | 区块 | 作用 |
|---|---|---|
| 1 | 概览 | 入库数 / 覆盖域名 / 通道数 / 告警数，以及从候选到入库的漏斗 |
| 2 | **覆盖率自评** | 每通道：请求数 / 解析数 / 被拦数 / 停止原因 |
| 3 | 来源分布 | 域名 Top N + 条形图（单域配额截断会写明） |
| 4 | 时间分布 | 按天聚合；无日期、只有相对日期的单独计数，不混进时间线 |
| 5 | 文档清单 | 标题 + 域名 + 时间来源 + 摘要 + 原文链接，按相关度排序；同文转载折叠在代表条目下 |
| 6 | 查询明细 | 每个变体打了几条、新增几条，用来解释「为什么只打了 3 次」 |
| 7 | 告警 | 被拦 / 结构变更 / 截断 / 脱敏，逐条列出 |

人名模式额外在文档清单之前插一块「候选人」（按机构分组的卡片 + 档位徽章 + 证据行）；普通任务里没有这一块。人名模式下文档清单改称「同名结果池」并标注：**这是裸姓名检索的原始池子，不是结论**，只有「已归因」条目经过机构锚点筛选。

第 2 块比「命中总数」更重要：少了它，读者无法判断「只有 12 条」到底是这个词冷门，还是我们被拦了。**一份不说自己缺什么的报告，和搜索结果页截图没有区别。**

## 快速开始

```bash
git clone https://github.com/Durian2005/keyword-search-aggregator.git
cd keyword-search-aggregator

python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

python -m kwsearch channels          # 列出通道并自检（不联网）
python -m kwsearch run "红黑树"       # 完整跑一次，顺手生成报告
```

跑完看 `report/红黑树/index.html`。

依赖只有两个必需项：`PyYAML`，以及一个 HTTP 客户端（`curl_cffi` 优先，`httpx` 兜底）。默认不装浏览器、没有 selenium、没有代理池。可选的 Scrapling 隐身档见下面专门一节。

想要快：`--no-body` 跳过正文抓取（实测 5 秒 vs 53 秒），摘要退回搜索页原文。

## 交互页面

不想敲命令就起页面：

```bash
python -m kwsearch serve        # 默认 127.0.0.1:8787，自动打开浏览器
```

不想碰命令行就**双击项目根目录的 `启动交互页面.bat`**（停服用 `停止服务.bat`）——它做的事就是上面这条命令，用的是项目自带 `.venv`，不需要单独装环境。

深色终端风单页：填关键词、勾「人名模式」、给机构/方向锚点，点开始抓取。**背后还是 `run_task` + `render`，和命令行同一份代码，没有第二个实现**——页面只是把 CLI 包了一层 HTTP。

- 进度逐行直播，收尾表与 CLI 一字不差；完成后报告在页面里直接预览，也可新窗口打开
- 同一时刻只跑一个任务（上游限速本来就是全局的，并发只会互相锁），第二个请求会被告知「稍等」
- 「最近任务」列表带报告入口；同一关键词重复跑会覆盖它的报告目录，历史数据在 SQLite 里
- 底部「历史数据」区可一键清空：先弹层列出每张表将删多少行，勾选确认后才执行；任务运行中会拒绝
- 只绑 `127.0.0.1`；`/r/` 静态文件锁死在报告目录内，`..`、盘符、Windows 保留字符一律 404
- 零新增依赖：服务是标准库 `http.server`，前端是内联 CSS/JS 的单文件 HTML

## 命令

| 命令 | 用途 |
|---|---|
| `channels` | 列出所有通道并做可用性自检，不联网 |
| `run <关键词>` | 完整跑一次任务并生成报告（`--dry` 只打印请求计划） |
| `discover <关键词>` | 只跑发现层，打印候选与断言；`--offline` 解析本地样本，`--expand` 试查询变体 |
| `probe <URL>` | 单 URL 探针：状态 / 耗时 / 大小 / 预览。**上线新通道前先跑它** |
| `page [URL...]` | 真的打开候选链接，检查 robots / 编码 / 挑战页 / 空壳页 |
| `extract [URL...]` | 抓取并抽取正文与发布时间，看抽得干不干净 |
| `report [task_id]` | 由已有任务重新生成 HTML（不给 id 取最近一次） |
| `serve` | 启动本地交互页面（浏览器里点着用，stdlib 服务，零新增依赖） |
| `db init` | 初始化数据库 |
| `db clear [--yes]` | 清空所有历史数据。**不加 `--yes` 只预览**（列出将删的任务与各表行数，一行不删）；加了才真删 |

`db clear` 是破坏性操作，所以有两道闸：命令行先打印将删什么、再要 `--yes`；交互页面则是「预览弹层 + 勾选确认」两步。清空只动 SQLite，已生成的报告 HTML 文件不受影响。

`run` 常用开关：`--mode quick|deep|watch`、`--max-docs N`、`--expand [N]`、`--require REGEX`、`--no-body`、`--no-report`、`--stealth`（见下节）。

## Scrapling 隐身抓取（可选，默认关闭）

默认链路是「TLS 指纹伪装的 HTTP 请求」（curl_cffi），遇到 Cloudflare Turnstile / Interstitial 这类**机器人挑战页**只能记 alert 放弃。第三档是可选的 Scrapling 隐身浏览器：用一个指纹伪装过的真实浏览器打开页面，从而能通过这类挑战。**默认完全关闭，不开和以前一模一样。**

```bash
pip install 'scrapling[fetchers]' && scrapling install   # 后者下载浏览器二进制，必跑

python -m kwsearch run "红黑树" --stealth                # 正文抓取切到隐身档
python -m kwsearch probe <URL> --fetcher scrapling       # 先拿单条 URL 试水
python -m kwsearch page <URL> --fetcher scrapling        # 批量试水，看判定表
```

交互页面里对应「高级选项 → 隐身抓取」勾选框；配置文件里是 `defaults.stealth.enabled: true`。三处等价，任选其一。

参数在 `channels.yaml` 的 `defaults.stealth` 段：`headless` / `solve_cloudflare` / `network_idle` / `disable_resources` / `humanize` / `use_camoufox` / `timeout_ms`，注释都写在配置里。

几条不会因为开了它而改变的事实：

- **robots 档位与隐身档无关**：是否放行由 `--robots-mode` / `crawl.robots_mode` 决定（默认 obey），隐身档只改「怎么发请求」，不改「允不允许发」；robots.txt 本身仍走轻量档取（不为一行规则启动浏览器）
- **不携带账号 Cookie**：当前实现没有登录态支持（历史红线已作废，这是现状描述）
- **出口 IP 就是本机 IP**：Scrapling 的 ProxyRotator 未接入
- **被拦照样记账**：隐身档不是万能的，挑战没过多半还是会拿到挑战页，照旧判 `challenge` 记 alert

### robots.txt 档位（可绕过，全留痕）

2026-10-22 起 robots.txt 从"必须遵守"改成三档显式能力（Scrapling 的 robots 设计是合规向的
`robots_txt_obey` 开关，本项目在此之上补了绕过档，但留痕纪律照旧）：

```bash
python -m kwsearch run "红黑树" --robots-mode record    # 查 robots 但不拦（强制抓取留痕）
python -m kwsearch run "红黑树" --robots-mode off       # 完全不查（--no-robots 等价）
python -m kwsearch run "红黑树" --robots-on-failure allow  # robots.txt 拉不到时放行（留痕）
python -m kwsearch page <URL> --robots-mode record      # S3a 同样可覆盖
```

| 档位 | 行为 | 默认 |
|---|---|---|
| `obey` | 按 RFC 9309 遵守 Disallow / Crawl-delay | ✅ 默认 |
| `record` | 查 robots 但不拦，Disallow 照抓，逐条 `forced` 留痕 | 可选 |
| `off` | 完全不拉 robots.txt | 可选 |

交互页面在「高级选项 → 反爬与合规」里提供同样的档位选择，**默认全部保守**（obey / deny / 隐身关闭）。
配置写法见 `channels.yaml` 的 `crawl.robots_mode` / `crawl.robots_on_failure`。
不管用哪一档，报告里都有「robots 覆盖」一节逐域列出依据；**政府站红线（.gov.cn）不受档位影响，永远拦截**。

### 人名模式

查一个人（尤其是张伟、刘洋这种大众姓名）时，重名问题在**查询层无解**：Bing 会把「姓名 + 任何第二个词」静默降级成第一个词的字面结果，所以你搜得越细，回来的越不相关。正确做法是**裸姓名捞一次池子，再在结果内归因**：

```bash
python -m kwsearch run "张军" --person --org "某某大学计算机学院" \
    --field "网络安全" --role "教授"
```

- 查询侧**默认只发裸姓名一次**（强制 person 档，任何后缀都会被清掉）；但给了机构时
  会多做两步检索动作，见下
- 归因侧用你给的锚点给每条结果打分：**强锚点**（机构）+ **弱锚点**（方向 / 身份），
  外加负锚点（演员、招聘、判决书 —— 同名不同人的常见来源，只在机构缺席时否决）
- **姓名必须真的出现在页面上**。机构对得上、整页却没有这个姓名，那是招生简章 / 师资列表
  这类「机构页面」，不是这个人的证据：不进卡片，只在告警里记账（否则用户会以为「一条都没找到」）
- **多个机构命中时选一个「主机构」**，其余记为「还提到」附在卡片上。把「甲大学」和「乙研究院」
  拼成一张卡等于凭空造出第三种身份；兼职、跳槽、合作、同名都长这个样子，判断留给看的人
- 每条证据带**发布日期并按时间倒序**，卡片标出「活跃 2021-03-05 ~ 2025-06-01」——
  这是「人物轨迹」最小可用的形态：先在哪、后来去了哪
- 输出**候选人卡片**，分四档：确认（机构 + 身份互相印证）/ 很可能（只有机构）/
  疑似（只有方向）/ 同名不相关；**不同机构绝不合并**，没有机构命中的一律折叠为
  「未匹配机构」，不冒充候选人
- 不给锚点也能跑：结果全部归入「未匹配机构」，报告里会明确标注「无法归因」
- 锚点太泛（「大学」「研究院」）或只给机构不给方向时，开跑前就会提示 —— 跑完 50 秒
  才发现「锚点没意义」是最冤的一种浪费

#### 机构锚点会触发检索动作（不只是打分）

中文高校官网通篇自称「我校」，字面机构名在页面里几乎不出现；大众姓名的裸姓名池又会被
名人同名者占满。所以给了机构时，检索侧会补三件事：

1. **官网域探测**：先用机构名本身在搜索引擎上查一发（如「某某大学计算机学院」），
   从结果的注册域名里取众数拿官网域（如 `xxx.edu.cn`）。候选**不进文档池**，
   查询日志里记为 `[机构探测]`
2. **百度单发 site: 查询**：百度通道把「裸姓名」换成「姓名 site:官网域」。
   百度对单人单次只有一发配额（第 2 次请求就出安全验证），这一发必须花在这里
3. **域名归因证据**：页面落在机构官网域上，等于机构锚点命中（matched 里标「（官网域名）」），
   与文本命中同权算强锚点。中文站「我校」「本院」的写法从此不再是漏判理由

如果给了机构却一条都没命中，报告会告警说明「裸姓名池可能被同名者占满」——
这是「检索没打中」，不是「这人没上网」。

## 它是怎么搭的

依赖方向**只能向下，不许回头**：

| 层 | 包 | 职责 | 碰网络 | 写库 |
|---|---|---|---|---|
| 配置 | `config` | `channels.yaml` → 带校验的 dataclass | ✗ | ✗ |
| 契约 | `models` | `Candidate` / `Doc` / `Mention` / `ChannelResult` | ✗ | ✗ |
| 发现 | `discover` | 关键词 → 候选 URL（唯一「问搜索引擎」的层） | ✓ | ✗ |
| 采集 | `fetch` | URL → (status, bytes)，只管拿到字节 | ✓ | ✗ |
| 抽取 | `extract` | HTML → `Doc`（正文容器打分、时间抽取） | ✗ | ✗ |
| 聚合 | `aggregate` | URL 规范化、相关度打分、SimHash 归并 | ✗ | ✗ |
| 脱敏 | `sanitize` | 入库前的 PII 遮罩与丢弃判定 | ✗ | ✗ |
| 存储 | `storage` | SQLite，只认 `models` 里的 dataclass | ✗ | ✓ |
| 展示 | `report` | DB → 单文件 HTML | ✗ | ✗ |
| 编排 | `pipeline` | 把上面串成「一次任务」 | ✓ | ✓ |
| 富化 | `enrich` | 抓正文 → 用正文重算相关度并重排 | ✓ | ✗ |
| 归因 | `person` | 人名模式：锚点打分、四档定级、按机构分组 | ✗ | ✗ |

这样拆的用处很实际：**换抓取档位时，解析逻辑一行不改**。抽取层不认识「字节是怎么来的」，所以接入渲染引擎、换 HTTP 客户端、换成离线样本回放，都只动 `fetch/`。

执行顺序：

```
建任务 → 逐通道采集 → 全局去重 → 脱敏/丢弃 → 打分排序
       → 抓正文 → 用正文重排 → 单域配额 → 入库 → 转载归并 → 人名归因（可选） → 出报告
```

四条硬规则，每条都对应一个已知的失败模式：

1. **通道故障只降级、不中断** —— 一个通道挂掉记 alert，其余继续。因为 B 站返回 412 就让整个任务失败，等于把「少一个来源」放大成「什么都没有」。
2. **入库前脱敏，没有例外分支** —— 正文抓到后还要再洗一次：那段文字来自第三方页面，没经过前面的清洗。
3. **截断必须留痕** —— 超过条数 / 单域配额 / 时间上限时 `task.truncated=1` 并写 alert。悄悄截断是最坏的。
4. **排序在入库前** —— 先排序再截断，保证被截掉的永远是分数最低的，而不是「运气不好排在后面的」。
5. **列表页不进库，但文章要捞出来** —— 栏目列表页（`/list38.htm`、`/677/list.psp`）和站点首页按 URL 形态识别，点开是一屏文章目录，不是一条结果。但**不直接丢**：抓下列表页，把锚文本里含关键词的文章链接捞出来当结果，链接从此直指正文（百度 `site:官网域` 返回列表页，就是因为列表里链着目标文章）。页内解析不出相关文章的才丢，且告警写清原因。机构官网探测**豁免**这条——那个场景要的恰恰是首页来认域名。

## 通道现状

`channels.yaml` 里同时记着每个通道的探测结论和日期，免得过两个月回来猜「当时为什么这么配」。

| 通道 | 类型 | 状态 | 约束 |
|---|---|---|---|
| Bing 网页 | serp | ✅ 启用 | 一页恒 10 条，翻页失效；多词中文有静默降级风险，靠通道层体检兜住 |
| 百度网页 | serp | ✅ 启用 | **单人单次配额**：第 2 次请求即出验证码（HTTP 仍 200），所以 `variants:false` + 只打一发；真实落地页取结果块 `mu` 属性 |
| 搜狗微信 | site_search | ✅ 启用 | 微信公众号文章；发布时间在 `timeConvert(unix秒)`，显式 UTC+8。链接是 `link?url=<token>` 中转链且 token 每次请求都轮换，所以另给一个「公众号+标题+日期」的业务键做跨跑批去重（否则同一篇每次跑批都算新发现） |
| B 站搜索 | site_search | ✅ 启用 | 20 条/页；`Referer` 必须带 `https://search.bilibili.com/`；412 是滚动配额，被拦即停 |
| GDELT | structured_api | ✅ 启用 | 请求间隔 ≥5s；中文短语覆盖极低；标题常是机翻 |
| Bing RSS | serp | ⏸ 停用 | `site:` 无效 |
| SearXNG | serp | ⏸ 停用 | 需要自建实例 |
| 360 / 搜狗 | serp | ⏸ 停用 | 页面可达，但结果块选择器未验证稳定、跳转链需额外还原 |

新增一个通道 = 在 YAML 加一段 + 在 `discover/` 注册一个 parser，主流程零改动。

## 红线与使用边界

**项目红线（2026-10-22 用户修订，替代 2026-10-21 口径）：只有一条 —— 不抓政府网站。**

- **不抓政府网站**：`.gov.cn` 等后缀硬拦截（`filter.block_host_suffixes`，默认开启且无绕过开关）。过滤层丢弃 + 抓取层拒绝双保险，命中记 `gov_blocked` 告警，请求根本不发。
- 2026-10-21 版红线（禁止恶意行为 / 不抓登录态 / 不引代理池 / 不存全文）**已作废**。
- **robots.txt 的遵守与绕过是显式能力**：`--robots-mode obey|record|off` 三档（默认 obey），`--robots-on-failure deny|allow` 管失败语义；record/off 档的每一笔强制抓取都进报告「robots 覆盖」清单，不做隐形绕过。
- 反爬相关（隐身抓取、robots 绕过）在交互页面里都是**可选项，默认关闭/遵守**。
- **PII 入库前遮罩保留**：手机号、身份证号、邮箱命中即打码 —— 这是报告质量规则（不遮会把报告变成通讯录），不再是红线。

## 已知限制

- Bing 匿名访问**一个词只有 10 条**，变体矩阵是唯一的扩量手段，天花板看得见
- **不做 JS 渲染**。纯前端渲染的站会被记为「疑似 JS 站」并跳过，不假装抓到了
- **人名搜索只做到「收集 + 归因提示」，没做实体消歧**。同名的人会被分成不同条目展示，但系统不会替你判断「这个张军是不是你要找的那个」—— 这需要至少两个锚点（单位、领域），而且最终得靠人看
- GDELT 的标题常是机器翻译，过滤规则对它豁免（否则整条通道会被清空）
